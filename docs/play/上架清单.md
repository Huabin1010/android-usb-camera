## 上传前必须先做

这些不改，包可以传上去，但审核或后续更新会卡住。

1. **换成自己的上传密钥。** 现在 `release` 仍用 Android debug 证书。debug 证书密码是公开的，不能当作长期上传密钥。在仓库外生成一把密钥，不要提交 keystore：

   ```bash
   keytool -genkeypair -v \
     -keystore upload-keystore.jks \
     -keyalg RSA -keysize 2048 -validity 10000 \
     -alias upload
   ```

   在 `flutter_app/android/app/build.gradle.kts` 的 `release` 里改用这把密钥，并打开 Play 应用签名。第一版上传后，Google 会保管应用签名密钥。

2. **上传 AAB，不要传 APK。** 新应用必须用 Android App Bundle：

   ```bash
   cd flutter_app && flutter build appbundle --release
   ```

   产物在 `flutter_app/build/app/outputs/bundle/release/app-release.aab`。

3. **隐私政策要有公开网址。** 相机和麦克风属于敏感权限，控制台必填 URL。[privacy.html](privacy.html) 是可直接托管的页面。放到 GitHub Pages 或其他 https 地址后再填，不要填仓库里的相对路径。

4. **照片和视频权限。** 清单里有 `READ_MEDIA_IMAGES` 和 `READ_MEDIA_VIDEO`。应用只是把自己拍的 JPEG / MP4 写进 `DCIM/Camera`，界面并不浏览用户相册。Play 对「读取全部照片和视频」查得很严。提交前建议删掉这两项权限；如果保留，就要在「照片和视频权限声明」里说明核心功能确实需要持续读取整个媒体库，否则容易被拒。

5. **个人开发者账号的封闭测试。** 2023 年 11 月 13 日之后新建的个人账号，正式版之前要先做封闭测试：至少 12 名测试员选择加入，并连续参与 14 天。组织账号没有这条。

### 数据安全

应用没有账号、广告和分析 SDK，也不会把预览、照片、录像、录音或设置上传到开发者的服务器。

- 「您的应用会收集或共享任何必要的用户数据类型吗？」选 **否**。
- 照片、视频、音频由用户主动拍摄，写入手机自己的 `DCIM/Camera`，不算收集。
- 主题、语言、工作台和预览预设只存在本机 `SharedPreferences`，卸载后清除。
- 因为没有离设备传输，加密传输问题选不适用 / 不收集数据即可。
- 用户可以在系统相册删除文件，也可以卸载应用。

如果以后加了崩溃上报、统计或云备份，这张表要改，并补进隐私政策。

### 内容分级问卷

按实际能力回答，不要为了低分级隐瞒相机。

- 暴力、性内容、粗口、赌博、酒类或毒品：都没有。
- 用户可以在应用内互相交流、分享位置或组成社交网络：否。
- 应用会分享用户的精确位置：否。应用不申请位置权限。
- 应用允许购买数字商品：否。
- 用户可以拍摄或录下周围的人和环境：是。这是相机应用的正常用途，文件只留在本机。
- 不是不受限制的网页浏览器，不是新闻应用。

## 权限和用途（审核说明可照抄）

| 权限 | 用途 |
| --- | --- |
| `CAMERA` | 预览和采集 USB 摄像头画面。不要求手机自带相机，`android.hardware.camera` 不是必需功能 |
| `RECORD_AUDIO` | 录像音轨，以及单独录音。音源可以是手机麦克风或设备麦克风 |
| `USB host` | 访问 UVC 摄像头、内窥镜或采集卡。`usb.host` 标记为非必需，避免没有 OTG 的设备被商店直接隐藏；没有 OTG 时应用打不开设备 |
| 存储（Android 9 及更早） | 把照片和视频写入 `DCIM/Camera` |
| `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` | 见上文，建议在提交前移除 |

插入已授权的匹配设备时，系统可以用 `USB_DEVICE_ATTACHED` 把应用拉到前台。应用不读取通讯录、短信、位置或已安装应用列表。

## 上架顺序

1. 换上传密钥，打出 3.10.0 的 AAB。
2. 托管 `privacy.html`。
3. 在 Play Console 创建应用，包名 `com.huanghuabin.usbcamera`。
4. 填商店信息、图形、数据安全、内容分级、目标受众和广告声明。
5. 先上传到内部测试，确认安装、权限和预览。
6. 个人新账号再走封闭测试 14 天，然后申请正式版。
