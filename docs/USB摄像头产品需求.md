# USB 摄像头产品需求说明

版本 1.0　日期 2026-11-11　状态：草案

本文约定当前要做的产品：一部跑在安卓手机上的 USB 摄像头应用。界面用 Flutter，预览、编码和 UVC 控制沿用归档在 `reference/` 的 AUSBC 引擎。对照产品是手机上的 USB Camera 12.3.1，用来划范围，不照搬它的广告和付费墙。

## 1. 背景

用户用 OTG 把 UVC 摄像头、内窥镜或标准采集卡接到手机上，需要立刻看到画面，并能拍照、录像、录音。系统相机不认这类设备。

引擎已经能打开 UVC、走 OpenGL 预览、把照片写入 `DCIM/Camera`、把录像打成 H.264 + AAC 的 MP4。原先的界面是 Jetpack Compose，现已归档。日常使用的是 Flutter 应用，包名 `com.huanghuabin.usbcamera`。改 Dart 可以热重载；改 native 引擎需要重新启动调试会话。

USB Camera 12.3.1 比我们多出一整条「离开界面继续工作，并向局域网或推流地址输出」的链路。那些能力大多不在当前引擎里，不能靠补几个按钮完成。

## 2. 目标

- 插上支持的 USB 视频设备后，用户能在十秒内看到预览，并完成拍照或开始录像。
- 常用调节（设备、分辨率、格式、方向、画面、音源、分段）都在左侧栏里完成，主画面不被弹层挡住。
- 下一版本离开应用界面后，已经开始的录像不中断；插入设备时能把应用拉到前台。
- 同一局域网里的另一台设备能看到预览。推流使用真实客户端，不再从空的 `AliyunPusher` 起步。

## 3. 非目标

本版不做，也不排进紧接着的下一版本：

- 广告、Pro 付费墙、隐藏横幅。
- Windows 虚拟摄像头或虚拟麦克风驱动。
- EasyCap 等非 UVC 协议（STK1160、EM2860、复合视频 PAL/NTSC/SECAM）。
- HEVC、AV1、SRT、系统播放声音混入录像。
- 开机自启、锁屏常亮画面、画中画、悬浮窗。
- 运动检测、FTP、邮件。这些排在水印和局域网预览之后单独评估。
- x86 模拟器包。当前只提供 `armeabi-v7a` 与 `arm64-v8a`。

## 4. 用户与场景

| 用户 | 场景 | 成功标准 |
| --- | --- | --- |
| 检测或内窥使用者 | 插上内窥镜，看清画面，拍一张或录一段 | 预览稳定，照片在相册 `DCIM/Camera`，录像可播放 |
| 值守使用者 | 摄像头插上后长时间录像，期间切到别的应用 | 下一版本：录像不因离开界面而停止 |
| 给别人看画面的人 | 手机当相机，另一台手机或电脑在同一网络里看 | 下一版本：打开一个本机地址就能看到预览 |
| 调试者 | 改界面文案、布局、状态 | 保存 Dart 文件后热重载，不必重装 native |

## 5. 范围

产品分三层。

| 层次 | 内容 | 本文件怎么用 |
| --- | --- | --- |
| Flutter 界面 | 左侧栏、快门、状态、关于 | 日常交付，必须保持可用 |
| 引擎 `libausbc` / `libuvc` / `libnative` | UVC、OpenGL、编码、写媒体库 | 只在界面做不到时才改 |
| 参考工程 `reference/` | 原 Compose 演示，含多路网格 | 不作为日常入口。多路网格迁到 Flutter 之前，以这里为准 |

## 6. 现状基线

下面这些已经在 Flutter 应用里，后续版本不能退掉。

- 单路 UVC 预览。默认 MJPEG、OpenGL。标准 UVC 采集卡可以开，非 UVC 协议不行。
- 插入后由系统弹出 USB 权限。没有权限时不能出画。
- 左侧栏：设备、画面、视频、效果、音频，底部是设置和关于。再次点击当前项或点预览区域收起。
- 底部：拍照 / 录像 / 录音切换、快门。录像中不能改模式。
- 视频：MJPEG 与 YUYV、旋转和翻转、分辨率列表。改格式或分辨率会重新打开预览。录像中不能改。
- 画面：亮度、对比度、饱和度、色调、增益、伽马、锐度、变焦，范围 0–100；自动对焦、自动白平衡。设备报告支持哪些才显示；一项都没报告时，八项滑杆都显示。
- 效果：黑白滤镜，灵魂和缩放动画。
- 音频：手机麦、设备麦、自动；可监听麦克风。
- 设置：录像分段为不分段，或每 1、5、10、30 分钟。
- 预览右上角显示帧率；录像中显示计时。
- 照片进 `DCIM/Camera`。录像为 MP4。单独录音为 MP3，写在应用外部目录，不进媒体库。
- 应用图标和关于页使用 `reference/design` 里的摄像头 SVG。
- 需要相机、麦克风权限；Android 13 及以上还需要读取图片和视频。

尚未进 Flutter、只在参考工程里的能力：多路网格（2、3、4 列，每路可单独拍和录）。Flutter 设置里只说明这一点，不提供网格。

## 7. 功能需求

优先级：P0 是基线，回归时必须仍在。P1 是下一版本要交付的。P2 单独立项，不阻塞 P1。

### 7.1 连接与预览

| 编号 | 优先级 | 需求 | 验收 |
| --- | --- | --- | --- |
| CON-01 | P0 | 枚举已连接的 USB 视频设备，用户点选后切换 | 列表能看到设备名。切换后画面来自新设备 |
| CON-02 | P0 | 首次使用弹出 USB 权限，拒绝后可重试 | 拒绝时不崩溃。重试能再次弹出权限 |
| CON-03 | P0 | 拔出设备后停止预览并提示等待 | 拔出后不再写新的录像帧。界面回到等待状态 |
| CON-04 | P1 | 声明 `USB_DEVICE_ATTACHED`，插入已授权设备时打开应用 | 应用在后台或未启动时，插入匹配设备能进入预览 |
| CON-05 | P1 | 按设备记住分辨率、格式、方向和画面参数 | 拔出再插入同一台设备，恢复上次选择。提供恢复设备默认 |
| CON-06 | P1 | 设备详情展示厂商、产品、USB 速度、UVC 版本 | 打得开的设备能看到这些字段；读不到的字段显示未知，不编造 |
| CON-07 | P2 | 同一物理设备内的多个子设备单独选择 | 有子设备时先选择再开预览 |

### 7.2 画面调节

| 编号 | 优先级 | 需求 | 验收 |
| --- | --- | --- | --- |
| IMG-01 | P0 | 八项 0–100 调节和自动对焦、自动白平衡按设备能力显示 | 不支持的项不出现。设备不报告能力时显示全部，并允许恢复默认 |
| IMG-02 | P0 | 旋转 0/90/180/270，上下翻转、左右翻转 | 预览立即变化。下次改分辨率后方向仍在 |
| IMG-03 | P1 | 把曝光、手动对焦、白平衡数值、电源频率、云台 pan/tilt/roll 包到 Kotlin，并按能力出现在画面页 | 设备不支持时不显示。数值范围来自设备，不把原始最大值当成滑杆上限 |
| IMG-04 | P2 | 预览上的双指缩放、单指平移 | 与 UVC 数字变焦分开，不互相覆盖 |

### 7.3 采集

| 编号 | 优先级 | 需求 | 验收 |
| --- | --- | --- | --- |
| CAP-01 | P0 | 拍照得到 JPEG，写入媒体库 `DCIM/Camera` | 相册能看到新照片。写入过程使用 pending，避免出现半张图 |
| CAP-02 | P0 | 录像得到 H.264 + AAC 的 MP4，可按设定分钟数分段 | 分段文件都能播放。0 表示不分段 |
| CAP-03 | P0 | 单独录音得到 MP3 | 文件可播放。和录像音轨不是同一条按钮 |
| CAP-04 | P0 | 录像或录音进行中，模式、分辨率、格式、分段不可改 | 界面上的对应控件不可用。正在写的文件不被截断成损坏文件 |
| CAP-05 | P1 | 前台服务保住相机和麦克风，离开界面后继续当前录像 | 按 Home 后录像仍在增长。回到应用能停止并看到成片。通知里能停止 |
| CAP-06 | P1 | 预览上叠加时间和一行自定义文字 | 录像文件里能看到叠加。关闭后预览和成片都没有字 |
| CAP-07 | P2 | 空间将满时停止并提示；FAT32 单文件接近 4GB 时切段 | 不会写出系统无法保存的超大文件 |
| CAP-08 | P2 | 用户用系统目录选择器指定 SD 卡或 U 盘 | 选择的目录在重进应用后仍有效，直到用户改掉 |

### 7.4 音频

| 编号 | 优先级 | 需求 | 验收 |
| --- | --- | --- | --- |
| AUD-01 | P0 | 音源为手机麦、当前设备麦、自动。自动在设备有麦时用设备麦 | 三种选择都能重新打开预览并生效。录像中不可改 |
| AUD-02 | P0 | 监听麦克风可开关 | 打开时能听到采集声。关闭后不再播放 |
| AUD-03 | P2 | 外置 USB 声卡优先于设备内建麦；与手机麦混音；混入系统正在播放的声音 | 各自独立开关。混入系统声音必须先得到媒体投影授权 |

### 7.5 网络输出

| 编号 | 优先级 | 需求 | 验收 |
| --- | --- | --- | --- |
| NET-01 | P1 | 本机提供一个 HTTP 或 RTSP 预览地址，界面展示该地址 | 同一局域网的另一台设备能打开并看到当前画面。冲突端口有明确提示 |
| NET-02 | P1 | 用现有 H.264 与 AAC 回调接到一个可用的 RTMP 客户端 | 填入地址后能推送，停止后对方不再收到新帧。不在空的 `AliyunPusher` 上补 TODO |
| NET-03 | P2 | 多个推流地址、SRT、插入后自动开服务 | 不进入 P1 验收 |

### 7.6 多路

| 编号 | 优先级 | 需求 | 验收 |
| --- | --- | --- | --- |
| MUL-01 | P2 | 把参考工程里的 2/3/4 列网格迁到 Flutter | 每路可单独预览。至少主路能拍照和录像。未完成前，设置页继续说明网格在参考工程 |

## 8. 交互

手机竖持为默认。界面保持深色。

- 左侧轨道宽 72dp。展开面板宽 300dp，贴在轨道右侧，不盖住轨道。
- 轨道图标顺序固定：设备、画面、视频、效果、音频；下方为设置、关于。顶部是品牌 SVG，不承担切换。
- 主预览铺满轨道和面板以外的区域。帧率和录像计时在预览右上。快门和模式在预览底部。
- 等待设备、打开失败、保存成功和保存失败都用一句人话，不用错误码。
- 录像中快门变为停止。停止后计时归零。
- 关于页展示品牌 SVG、应用说明和联系邮箱 `765067602@qq.com`。

P1 的前台服务通知只提供「停止录像」和「回到应用」，不在通知里改分辨率。

## 9. 非功能需求

- 应用 `minSdk` 24，`targetSdk` 35。库模块可以保持更低的 minSdk，但打进 Flutter 包的 ABI 只有 `armeabi-v7a` 和 `arm64-v8a`。
- 预览帧不因界面刷新而重建 `TextureView`。帧率数字更新不得导致重新打开相机。
- 照片和录像走媒体库 `RELATIVE_PATH`，不依赖已废弃的公共目录直写。
- Dart 界面在 `./scripts/dev.sh` 的 debug 会话里可热重载。native 改动必须热重启或重新执行脚本。
- 没有插入真实 UVC 设备时，应用停在「等待 USB 摄像头」，不能崩溃。
- 构建环境没有摄像头。自动化只覆盖纯逻辑：计时格式、录像中拒绝切换模式、平台状态解析。真机预览、拍照、录像由人在插上设备后验收。

## 10. 版本计划

| 版本 | 包含 | 不包含 |
| --- | --- | --- |
| 当前基线 | 第 6 节全部 P0 | 后台录像、局域网、推流、多路网格 |
| 下一版本 | CON-04、CON-05、CON-06、IMG-03、CAP-05、CAP-06、NET-01、NET-02 | EasyCap、HEVC/AV1、SRT、运动检测、FTP、邮件 |
| 之后 | 按第 7 节 P2 逐项单独立项 | 不与下一版本绑成一次发布 |

下一版本的建议顺序：先前台服务和插入拉起，再设备记忆和补齐 UVC 调节，然后时间和文字水印，最后 HTTP/RTSP 与 RTMP。推流依赖编码回调，不依赖水印，但水印更小，先做完能单独交付。

## 11. 验收

基线回归（每次改界面都做）：

- 无设备时打开应用，看到等待提示、左侧栏和快门，不崩溃。
- 插入 UVC 并授权后出画，帧率数字会变。
- 拍照后相册出现新 JPEG。录像停止后能播放 MP4。
- 录像过程中不能改模式和分辨率。
- 左侧每一项都能展开和收起。关于页能看到品牌 SVG。

下一版本额外验收：

- 录像开始后按 Home，文件仍在增长；从通知停止后，文件可播放。
- 拔出再插入同一设备，分辨率和画面参数与上次一致。
- 另一台设备打开界面上的地址，能看到预览。
- RTMP 地址可用时能推送；地址错误时有失败提示，预览不中断。

## 12. 风险与依赖

- 不同 UVC 设备报告的能力和真实效果不一致。调节项必须按设备能力显示，读不到就标未知。
- 部分手机对 USB 安装有确认。调试安装失败时需要用户在手机上允许，而不是改应用逻辑。
- 离开界面继续录像依赖前台服务和通知权限。服务被系统杀掉时，必须把已写的文件收尾，不能留下无法播放的半截 MP4。
- 局域网预览会暴露画面。默认只监听本机局域网，不自动做 UPnP 端口映射。界面要写明谁能看到。
- 多路网格、EasyCap、HEVC 都是另一条实现，不能塞进 P1 来「顺便做完」。
