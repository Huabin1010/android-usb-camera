# 与 USB Camera 的功能对照

对照对象是手机上已安装的 **USB Camera 12.3.1**（`com.shenyaocn.android.usbcamera`，versionCode 763）。结论来自它的安装包清单、界面文案和类名，没有在真机上把每个开关都点过。文案里标明「仅 Pro 版」的功能，下面单独标出。

原来的 Android 工程已经归档在 `reference/`。下面说的「演示」指那套 Compose 界面；现在日常用的是仓库根目录的 Flutter 应用，相机引擎仍是 `reference/libausbc`。

我们这边分三层看：

| 标记 | 含义 |
| --- | --- |
| 演示已有 | 当前 Compose 演示应用里能直接用 |
| 库有，界面没有 | `libausbc` / `libuvc` 已经有接口，演示没做入口 |
| 没有 | 工程里没有对应实现 |

演示应用现在能做的是：单路 UVC 预览、左侧栏展开后选择设备、分辨率、MJPEG/YUYV、画面方向、画面调节、特效、音源和录像分段，以及设置里的多路预览和关于。拍照、录像、单独录音、听麦克风仍在画面下方。录像是 H.264 + AAC 的 MP4，照片进 `DCIM/Camera`。设备报告支持的调节项才会出现；一项都没报告时，八项滑杆都会显示。

---

## 1. 采集和设备

| 功能 | USB Camera | 我们 | 说明 |
| --- | --- | --- | --- |
| UVC 摄像头、内窥镜 | 有 | 演示已有 | 预览默认 MJPEG、OpenGL |
| YUYV 预览 | 有，可改视频格式 | 演示已有 | 左侧「视频」里可选 MJPEG / YUYV，切换后会重新打开预览 |
| UVC 采集卡 | 有 | 演示已有 | 标准 UVC 采集卡可以开。非 UVC 协议的卡不行 |
| EasyCap（STK1160 / EM2860 等） | 有，独立 `libEasyCap.so`，复合视频 1–4 路、PAL/NTSC/SECAM | 没有 | 这是另一套采集协议，不是把 UVC 分辨率列表做出来就能覆盖 |
| 一个物理设备里的多个子设备 | 有，新设备含子设备时弹选择框 | 没有 | 我们按 `UsbDevice` 整台切换 |
| 插入后弹出 USB 权限 | 有 | 演示已有 | `USBMonitor` 申请权限 |
| 插入后自动打开应用 | 有，`USB_DEVICE_ATTACHED` | Flutter 已有 | 清单声明了 UVC 相关 `device_filter`，已授权设备插入可拉起应用 |
| 记住每台设备上次的分辨率和参数 | 有，可重置为设备默认 | 部分 | Flutter 会持久化分辨率、帧率、格式、方向、音源、分段和工作台模式；尚未按设备分别记，也没有「恢复设备默认」 |
| 设备信息（厂商、USB 速度、UVC 版本） | 有 | 没有 | 设备列表只有名称和厂商号 / 产品号 |
| 安全弹出后再拔设备 | 有 | 没有 | 拔出时会关预览，没有「先弹出」这一步 |
| 多路同时预览 | 有叠加和小窗；我们是网格 | 演示已有 | 我们是 2 / 3 / 4 列卡片，每路可单独拍和录。他们是主画面加另一路摄像头叠加 |
| Quest / Horizon 头戴摄像头权限 | 声明了 `horizonos.permission.USB_CAMERA` | 没有 | 只是清单声明，不代表我们要做头戴设备 |
| x86 / x86_64 | 安装包里有四个 ABI | 没有 | 当前只编 `armeabi-v7a` 和 `arm64-v8a` |

## 2. 画面调节

UVC 标准里很多调节项，底层 `UVCCamera` 已经有 native 接口。`CameraUVC` 只往上包了一部分，演示又只用了亮度。

| 功能 | USB Camera | 我们 |
| --- | --- | --- |
| 亮度 | 有 | 演示已有 |
| 对比度、饱和度、色调、增益、伽马、锐度、变焦 | 有 | 演示已有 | 左侧「画面」，范围按 0–100。设备报告支持时才显示 |
| 自动对焦、自动白平衡 | 有 | 演示已有 | 同一页的开关 |
| 曝光、手动对焦、光圈、逆光补偿 | 有 | 原生有，Kotlin 没包。`UVCCamera` 有 native 方法，`CameraUVC` 没有对应函数 |
| 白平衡数值、自动对比度、电源频率（50/60Hz） | 有 | 原生有，Kotlin 没包 |
| 云台 pan / tilt / roll | 有 | 原生有，Kotlin 没包 |
| 水平翻转、垂直翻转 | 有 | 演示已有 | 左侧「视频」 |
| 旋转 90 / 180 / 270、强制横屏 | 有，录制和推流时会锁住旋转 | 演示已有旋转和翻转。录像中不能改。没有单独的强制横屏 |
| 双指缩放、单指平移预览 | 有 | Flutter 预览手势：双指捏合 1x–8x，放大后可单指拖动；双击复位。库里的 zoom 滑杆仍是 UVC 数字变焦 |
| 丢弃损坏的 JPEG 帧 | 有 | 没有 |
| HDR 色彩空间提示 | 有 | 没有 |
| 按设备能力显示或隐藏调节项 | 有，文案写「这些选项基于你的 USB 视频设备」 | 没有。亮度滑杆不判断设备支不支持 |

## 4. 拍照和录像

| 功能 | USB Camera | 我们 |
| --- | --- | --- |
| 拍照存 JPEG | 有 | 演示已有，写入 `DCIM/Camera` |
| 从视频流截一张，或走设备静态图像接口 | 有，并区分「方法 2」；不支持时提示改视频格式 | 只有预览帧转 JPEG。没有第二套静态图像捕获 |
| 录像 MP4 | 有，可自定义码率 | 演示已有。码率在编码器里固定，界面不能改 |
| FLV | 有 | 没有 |
| H.264 / AAC 编码数据回调 | 有，用于推流 | 库有，界面没有。`captureStreamStart()` 和 `IEncodeDataCallBack` |
| HEVC / H.265、AV1 | 有，含码率、关键帧间隔、旁路直出 | 没有。视频编码只有 `H264EncodeProcessor` |
| 设备原流旁路（MJPEG / H.264 / HEVC 不再编码） | 有。旁路时文字和水印叠加会失效 | 没有。预览一律进 OpenGL，录像再编码成 H.264 |

| 定时分段 | 有，每段长度，0 表示不分段 | 演示已有 | 左侧「设置」：不分段，或每 1 / 5 / 10 / 30 分钟 |

| FAT32 约 4GB 自动切成 3.5GB | 有 | 没有 |
| 录制中暂停 | 对方文案写「录像无法暂停」 | 同样只有开始和停止 |
| 录像文件名带设备名 | 有 | 没有 |
| 照片、录像写入 GPS EXIF | 有 | 没有。也没有定位权限 |
| 存到用户选的 SD 卡或 U 盘目录 | 有，SAF | 没有。只进应用目录或媒体库 `DCIM/Camera` |
| 运动检测录像 | 有，`libmotiondetection.so`，可设超时和空间上限 | 没有 |
| 多路网格里每路单独拍、录 | 对方是主画面操作 | 演示已有 |

## 6. 网络输出

这是差距最大的一块。对方是一台可以对外服务的相机；我们只有「把编码数据交出来」的钩子，没有服务器。

| 功能 | USB Camera | 我们 |
| --- | --- | --- |
| 本机 IP 摄像头网页（HTTP，可选 HTTPS / RTSPS） | 有，页面在 `assets/www`，可显示已连接客户端 | 没有 |
| 二维码把地址加到另一台手机、iOS 或 Windows | 有，并建议用 `.local` | 没有 |
| RTSP 服务，端口冲突会提示 | 有，`libstreaming.so` | 没有 |
| RTMP 推流，可同时推多个地址 | 有 | 没有。`AliyunPusher` 每个方法都是 `TODO` |
| SRT 推流，含更多 SRT 选项 | 有，`SRTPublisher` | 没有 |
| RTMP 上的 HEVC / AV1（enhanced RTMP，文案写可用于 YouTube） | 有 | 没有 |
| 插入后自动打开 IP 服务、RTSP 或开始推流 | 有 | 没有 |
| 只开服务、不打开界面 | 有 | 没有 |
| FTP 上传手动录像和运动检测录像，传完可删原文件 | 有 | 没有 |
| 运动检测后发邮件并附快照 | 有，SMTP | 没有 |

Pro 版包名是 `com.shenyaocn.android.usbcamerapro`。免费版会检测 Pro 是否已安装。哪些开关真正被 Pro 拦住，要以运行时为准，不能只凭「此功能仅在 Pro 版可用」这句文案。

## 8. 建议先补什么

按「演示里就能感到缺」和「库里已经有、只差界面」分开。

上面「只差界面」的四项已经接到左侧栏：画面调节、YUYV、音源、旋转翻转、录像分段。

**要新写一条链路：**

1. 前台服务，让退出界面后预览、录像还能继续。插入 USB 时能把应用拉起来。
2. 本地 RTSP 或 HTTP 预览。推流先把 `IEncodeDataCallBack` 接到一个真正的 RTMP 客户端，不要从空的 `AliyunPusher` 开始。
3. 时间、文字水印。运动检测和邮件、FTP 放在这之后。
4. EasyCap、HEVC/AV1、SRT、系统声音混音、SD 卡目录选择，各自都是独立工程，不和上面的界面补齐绑在一起。

底层已经有、但业务没包的 UVC 项（曝光、手动对焦、白平衡数值、pan/tilt）适合在做调节面板时一并包出来，按设备能力决定显不显示。
